# Руководство оператора: Региональный тест ДАВО «Заря» — 74 РО

Документ описывает полную последовательность вызовов UI-контракта `ZaryaUI` для проведения регионального теста опроса Совета регионального отделения Челябинской области партии «Рассвет». Содержание вопросов взято из файла `Региональный тест … 74 РО.csv`.

---

## Условные обозначения

- **Орган**: `"74.СОВ"` — Совет регионального отделения, Челябинская область (код 74)
- **Адреса-примеры**: `0xM01` … `0xM12` — условные адреса 12 членов Совета
- **Длительность голосования**: `604800` секунд = 7 дней; для тестовой сети можно взять `300` (5 минут)
- **Выполнение голосования**: функция `executeVoting(votingId, minimumQuorum, minimumApprovalPercentage)` из `Zarya.sol` (наследуется `ZaryaUI`). Кворум `7` — для реальной работы органа; во время тестирования работает `1`
- **Блокнот голосований**: каждый вызов `propose*` или `proposeMembership` создаёт уникальный `votingId` — автоинкремент начиная с 1. Идентификаторы нарастают строго по порядку создания

---

## Шаг 1: Инициализация контракта — добавление всех 12 членов

`initializeOrgansReadable` может быть вызвана **ровно один раз** за жизнь контракта. За один вызов передаются параллельные массивы органа и адреса участника. Все 12 членов передаются сразу — никакого голосования за добавление не нужно.

```
zaryaUI.initializeOrgansReadable(
    organIds = [
        "74.СОВ", "74.СОВ", "74.СОВ", "74.СОВ",
        "74.СОВ", "74.СОВ", "74.СОВ", "74.СОВ",
        "74.СОВ", "74.СОВ", "74.СОВ", "74.СОВ"
    ],
    members = [
        0xM01, 0xM02, 0xM03, 0xM04,
        0xM05, 0xM06, 0xM07, 0xM08,
        0xM09, 0xM10, 0xM11, 0xM12
    ]
)
```

После одного вызова в органе `74.СОВ` сразу зарегистрированы **все 12 членов**.

> Проверка: `zaryaUI.checkMembership(0xM01, "74.СОВ")` должна вернуть `true`.

> Шаг 2 (добавление через голосование) убран — он больше не нужен.

## Шаг 2: Настройка схемы матрицы

### Автоматически через forge script (рекомендуется)

Схема полностью описана в `script/ZaryaUI.s.sol`. Запуск:

```bash
MEMBER_01=0x... MEMBER_02=0x... ... MEMBER_12=0x... \
  forge script script/ZaryaUI.s.sol \
  --rpc-url <RPC_URL> \
  --broadcast \
  --sender <DEPLOYER_ADDRESS> \
  --private-key <DEPLOYER_KEY>
```

Скрипт выполняет в одном широковещательном сеансе:
1. Деплой `ZaryaUI`
2. `initializeOrgansReadable` со всеми 12 членами
3. Все `proposeThemeLabel`, `proposeStatementLabel`, `proposeCategory`, `proposeDecimals` для 24 вопросов — каждое голосование сразу закрывается (`duration=1s`, `quorum=1`)

В результате контракт полностью готов к раунду ответов (Шаг 3) без каких-либо ручных транзакций.

---

### Справочник схемы (для ручного воспроизведения через abi.ninja)

Схема состоит из трёх вложенных слоёв:

1. **Метка темы (Theme)** — название столбца `x` в матрице (`proposeThemeLabel`)
2. **Метка высказывания (Statement)** — строка `y` в контексте столбца `x` (`proposeStatementLabel`)
3. **Метка категории или точность (Category / Decimals)** — доступные варианты ответа или кол-во знаков после запятой

Функции `proposeThemeLabel` и `proposeStatementLabel` **не требуют членства** для создания предложения, однако проходят через голосование. Функции `proposeCategory` и `proposeDecimals` требуют членства в органе.

Все 12 членов голосуют на каждом из этих голосований через `vote(votingId, true, "74.СОВ")`. Исполнение — через `executeVoting(votingId, 7, 51)`.

### 2.1 Категориальная матрица S_Y — 16 столбцов

Для каждого столбца `x` выполняются действия:
1. `proposeThemeLabel(true, x, "<Тема>", 604800)`
2. `proposeStatementLabel(true, x, 0, "<Высказывание>", 604800)`
3. Для каждой категории: `proposeCategory("74.СОВ", x, 0, <id>, "<название>", 604800)`

Категориям назначаются числовые идентификаторы (`uint64`), перечисленные ниже.

### 2.2 Числовая матрица S_X — 8 столбцов

Для каждого столбца `x` выполняются: Theme → Statement → Decimals. Функция `proposeDecimals` требует членства в `"74.СОВ"`.

> **Кодирование числовых значений**: контракт хранит `uint64`. Если `decimals = 2`, то хранимое значение умножается на `100` перед записью и делится на `100` при чтении. Например, `150000.50` хранится как `15000050`. При `decimals = 0` значение передаётся как есть.

## Шаг 3: Раунд голосований по наполнению матрицы

После утверждения всей схемы начинается основной раунд: каждый из 12 членов передаёт свой ответ по каждому из 24 вопросов.

**Паттерн для одного ответа:**

```
# 1. Любой член органа выдвигает предложение (обычно сам автор ответа)
votingId = zaryaUI.proposeCategoricalValue(
    "74.СОВ",
    <x>,          # индекс столбца в S_Y
    <x>,          # y = x (диагональ, обязательно!)
    <categoryId>, # числовой ID выбранной категории
    <0xMXX>,      # адрес автора ответа (dataOriginator)
    60            # duration: 60 секунд на тестовой сети
)

# 2. Один член органа голосует «за» (кворум = 1)
zaryaUI.vote(votingId, true, "74.СОВ")  # достаточно 1

# 3. Исполнить после истечения duration
zaryaUI.executeVoting(votingId, 1, 51)
```

> **Оптимизация quorum=1**: на этапе тестирования каждый член сам выдвигает и тут же одобряет свой ответ. Итого на ячейку = **3 транзакции** (propose + vote + execute) вместо 14.

Для числовых ячеек вместо `proposeCategoricalValue` используется `proposeNumericalValue` с той же сигнатурой, но с `uint64 numericalValue` вместо `categoryId`.

### 3.3 Порядок сбора ответов

Каждый из 12 членов самостоятельно и независимо подаёт свои ответы по всем 24 вопросам. Для каждой ячейки создаётся ровно **одно** голосование с `dataOriginator = адрес отвечающего`.

При `minimumQuorum = 1`:
- 1 `propose` + 1 `vote` + 1 `execute` = **3 транзакции** на ячейку
- 12 членов × 24 вопроса = **288 голосований**
- Итого: 288 × 3 = **864 транзакции**

> Если в дальнейшем нужно голосование большинства (продакшн), задать `minimumQuorum = 7` и `vote` от всех 12 членов: 288 × 14 = **4 032 транзакции**.

Рекомендуется задать `durationInSeconds = 60` (1 минута) для тестовой сети. Можно параллельно открывать несколько голосований, не дожидаясь исполнения каждого предыдущего.
